## 📋 Resumo Executivo

A versão 2.2.0 do ORQUESTRA marca um avanço significativo em três frentes estratégicas:
**governança de dados**, **segurança de acesso** e **qualidade operacional**.

Esta release torna a plataforma pronta para ambientes corporativos com múltiplos perfis de
usuário — incluindo suporte nativo a usuários somente-leitura com integração LDAP —, expande
as capacidades do wizard de criação de pipelines com importação em massa e rastreabilidade de
lineage desde a criação, e entrega melhorias operacionais que tornam o diagnóstico de falhas
mais rápido e o processo de deploy mais seguro e previsível.

> **Impacto para gestores:** maior controle sobre quem pode executar ou modificar pipelines,
> sem fricção para quem precisa apenas consultar dados.
>
> **Impacto para analistas e engenheiros ETL:** criação de pipelines mais ágil, lineage
> integrado ao fluxo de cadastro e notificações de erro mais precisas para triagem de incidentes.

## 🔐 Governança e Segurança de Acesso

### Controle de Acesso por Perfil — Viewer Mode

Usuários com perfil **Viewer** no Airflow agora têm acesso completo ao ORQUESTRA em modo
somente-leitura. Todos os dados da plataforma — pipelines, jobs, logs, lineage e informações
de governança — continuam acessíveis normalmente. O que muda é que botões de criação, edição,
execução e exclusão ficam automaticamente ocultos para esse perfil.

**O que isso significa na prática:**
- Gestores, auditores e analistas de negócio podem consultar a plataforma sem risco de alterações acidentais.
- O perfil é detectado automaticamente no login — nenhuma configuração adicional é necessária.
- Compatível com autenticação LDAP corporativa.

**Controles ocultos para Viewer:**

| Tela | Botões ocultos |
|---|---|
| Pipelines | + Novo Pipeline, ⬆ Importar Sequence, ✎ Editar, ⊘ Inativar, Gerar DAG, ▶ Executar |
| Jobs | ✎ Editar job, Salvar ordem, + Adicionar job, Colar lista |
| Logs | ↺ Reexecutar pipeline |
| Governança | 🏷 Classificar objeto, ✎ Editar responsável |

---

### Autenticação Dual-Auth para Consultas (Usuário Sistêmico)

Para garantir que usuários Viewer consigam buscar e visualizar dados mesmo sem permissão de
disparar DAGs diretamente no Airflow, o ORQUESTRA passa a utilizar um **usuário sistêmico
dedicado** (`ORQUESTRA_SYSTEM_AUTH`) para todas as operações de leitura e consulta.

Operações de escrita, edição e execução continuam sendo realizadas com o usuário logado,
preservando a rastreabilidade de todas as ações. A configuração é feita via Airflow Variable,
sem necessidade de alteração de código.

**Benefícios:**
- Viewers têm experiência completa de consulta, sem erros de permissão.
- Rastreabilidade de quem fez o quê permanece intacta para operações críticas.
- Gestão centralizada da credencial sistêmica via interface do Airflow.

## 🧩 Novas Funcionalidades

### Etapa de Lineage no Wizard de Criação de Pipeline

O wizard de criação e edição de pipelines passou de **6 para 7 etapas**. A nova etapa
**"Lineage"**, inserida entre Jobs e Revisão, permite cadastrar as origens e destinos de dados
de cada job diretamente durante a criação do pipeline.

Assim que o pipeline é salvo, as informações de lineage ficam disponíveis imediatamente na
tela de Governança — sem necessidade de cadastro posterior.

**Fluxo atualizado do wizard:**

```
Identificação → Agendamento → Parâmetros → Jobs → Lineage → Revisão → Confirmação
```

---

### Importação de Jobs via CSV no Wizard

No passo de Jobs do wizard, agora é possível **colar uma lista em formato CSV** para importar
múltiplos jobs de uma vez, sem precisar cadastrá-los individualmente.

**Formato aceito:**
```
nome_do_job, tipo, comando
extrai_clientes, SQL, dbo.sp_extrai_clientes
transforma_pedidos, Python, transformacoes.processa_pedidos
envia_relatorio, HTTP, https://api.interna/relatorio/dispara
```

Agiliza o cadastro de pipelines com muitos jobs e reduz o tempo de onboarding de novos fluxos.

---

### Modal de Lineage do Pipeline na Grid

Na listagem de pipelines, o botão de lineage agora abre um **modal com a visão completa de
lineage** do pipeline selecionado — mostrando todos os jobs com suas origens, transformações e
destinos, no mesmo visual da tela de Governança.

Não é mais necessário navegar para outra tela para ter essa visão — ela está disponível
diretamente da listagem, a um clique.

## ⚙️ Administração da Plataforma

### Gerenciamento de Tipos de Job (CRUD Administrativo)

Nova tela administrativa para **gerenciar os tipos de job** disponíveis no wizard.

**Tipos suportados:** SQL, Python, Bash/Shell, Spark, dbt, DataStage, SSIS, HTTP/REST, StoredProc.

**Capacidades:**
- Criar novos tipos de job.
- Editar nome e configurações de tipos existentes.
- Ativar ou inativar tipos sem excluí-los.
- Controlar se o passo de lineage é exibido para aquele tipo de job.

Acesso restrito a usuários com perfil administrador no ORQUESTRA.

## 🛠️ Melhorias Operacionais

### Notificação de Erro com Identificação do Job Falho

As notificações de falha enviadas ao **Microsoft Teams** agora identificam exatamente qual job
causou o erro na execução do pipeline.

| Antes | Agora |
|---|---|
| *"Uma ou mais tasks falharam."* | *"Job **XYZ** falhou na execução."* |

Reduz o tempo de triagem de incidentes — a equipe vai diretamente ao job problemático sem
precisar vasculhar logs manualmente.

---

### Suporte Ampliado a Tipos de Job na DAG Factory

A DAG factory foi corrigida para suportar todos os tipos de job da plataforma:
**Bash/Shell**, **SQL direto**, **HTTP/REST** e **StoredProc**.

Variações de nomenclatura são normalizadas automaticamente. A configuração de conexão SSH,
antes global, passa a ser configurável por pipeline — maior flexibilidade para ambientes com
múltiplos servidores.

---

### Script de Deploy Completo Idempotente

Novo arquivo `sql/deploy_full.sql` centraliza toda a estrutura de banco do ORQUESTRA.
**Idempotente** — pode ser executado múltiplas vezes sem efeitos colaterais, criando apenas
o que ainda não existe. Garante consistência entre DEV, HML e PROD.

## 🧪 Artefatos de Teste e Validação

Esta versão inclui um conjunto de artefatos para validação dos principais fluxos:

| Pipeline de Teste | Tipo | O que valida |
|---|---|---|
| `ORQUESTRA_TESTE_PROC` | StoredProc | Execução de stored procedure SQL |
| `ORQUESTRA_TESTE_PYTHON` | Python | Import de módulo + função `run()` |
| `ORQUESTRA_TESTE_SHELL` | Bash | SSHOperator + conectividade SSH |

Podem ser usados como smoke tests após cada deploy.

## 🚢 Deploy

**1. Atualizar banco de dados:**
```bash
docker cp sql/deploy_full.sql <container-sqlserver>:/tmp/
docker exec <container-sqlserver> /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U sa -P '<senha>' -C -d orquestra_dev -i /tmp/deploy_full.sql
```

**2. Configurar usuário sistêmico (Airflow Variable):**
```bash
B64=$(echo -n 'usuario_sistemico:senha' | base64)
docker exec <scheduler> airflow variables set ORQUESTRA_SYSTEM_AUTH "Basic $B64"
```

**3. Deploy da aplicação:**
```bash
git pull origin claude/peaceful-planck-5Hg5k
docker restart airflow-ui
docker cp dags/ <scheduler>:/opt/airflow/dags/
docker cp dags/ <worker>:/opt/airflow/dags/
```

**4. Validar com os pipelines de teste:**
- Executar `ORQUESTRA_TESTE_PROC`, `ORQUESTRA_TESTE_PYTHON` e `ORQUESTRA_TESTE_SHELL`
- Todos devem concluir com status `success`
- Logar com usuário Viewer e confirmar que botões de edição estão ocultos
